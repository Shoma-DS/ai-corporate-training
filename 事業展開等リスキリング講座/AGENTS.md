# 事業展開等リスキリング講座 専用ルール

このファイルは `事業展開等リスキリング講座/` 配下にだけ適用する。親の `AGENTS.md` と矛盾する場合、この配下のスライド様式・成果物構成については本ファイルを優先する。既存の `講座/` には適用しない。

## 制度適合

- 作業前に `../skills/business-expansion-reskilling-builder/SKILL.md` と同スキルの `references/eligibility-gate.md` を読む。
- 講座名、対象者、各回テーマは、特定の職務とその直接業務が分かる表現にする。
- DX、生成AI、デジタルリテラシー、マナー、概念理解、汎用プロンプトだけの講座にしない。
- 受講者が職務で作る成果物、入力情報、処理手順、確認者、完了条件を明記する。
- 受給可否を断定しない。制度要件、助成率、期限、様式は確認日と一次資料URLを添え、最新資料と管轄労働局等で確認する旨を書く。
- 演習はダミーまたは匿名化データを使い、顧客企業の本番成果物を研修内で受託制作しない。

## スライド様式

- 正本は各回の `slides.json` と、そこから生成する編集可能な `講義スライド.html` とする。提出・配布用に `講義スライド.pdf` を作る。
- 1枚1メッセージとし、通常スライドの箇条書きは2〜5項目、具体例は原則1つ、受講者アクションも原則1つにする。
- 120分あたり16〜24枚を基本にし、講義、実演、動画一時停止ワーク、自己確認を組み合わせる。
- `isometric-corporate-clean`、高密度カード型、固定ワイヤーフレーム、全ページ目次ストリップ、章見出し/現在位置スライド、全面ラスター画像を必須にしない。
- スライドを1枚の生成画像として作らない。編集可能HTMLとテキストを維持し、必要な公式画面やダミー例だけを画像として添える。
- 配色は温かい白、チャコール、コバルト、イエローを基本とし、余白と大きな文字を優先する。

## eラーニング

- 録画動画とLMSによる非同期受講を前提にする。
- ワークは「ここで動画を一時停止して○分ほど取り組み、終わったら再生してください」と案内する。
- チャット、挙手、ライブ発表、相互レビューを前提にしない。
- LMSで修了日、受講開始・終了日時、受講時間数、進捗率を記録できることをパンフレットに記載する。
- 修了条件、確認テスト、課題提出、受講可能期間を明示する。

## パンフレット

- 正本は `全体/<講座名>_講座カリキュラムパンフレット.html` とし、同名PDFを作る。
- 表紙はHTMLテキストとCSSで編集可能にしてよい。既存講座の生成ラスター表紙は本コンテキストでは必須にしない。
- 対象職務、直接業務、到達点、標準学習時間、各回カリキュラム、演習成果物、LMS記録、修了条件、情報管理、制度確認上の注意を単体で理解できるようにする。
- 会社名、価格、連絡先、顧客情報、申請書類の実物、非公開リンクを入れない。

## GitHub Project

- 新しい講座案や教材ネタは `../skills/training-idea-project-manager/SKILL.md` で登録する。
- この配下の案は原則 `制度区分=事業展開等リスキリング` とし、対象職務、直接業務、成果物、職務直結度を埋める。
- 非公開情報を含む可能性がある場合は公開Issueを作らず、非公開ProjectのDraft itemを使う。
