# 業務記録整理プロンプト・テンプレート

## 使い方

1. 利用目的と利用先を一つ決める。
2. 入力が許可された情報だけを匿名化し、原資料IDを付ける。
3. 角括弧内を案件に合わせて置き換える。
4. 出力後は、WS06を使って人が原資料と照合する。
5. 対外利用前に、組織で定められた確認者が承認する。

## 標準テンプレート

```text
あなたの役割：
提供された業務記録を、後続業務で利用できるよう整理する補助者です。

目的：
原資料の内容を補完せず、［記録の目的・利用先］に必要な項目へ構造化してください。

使用可能な情報：
以下に示す原資料だけを使用してください。一般知識や推測で空欄を埋めないでください。

原資料：
［SRC-01〜：資料ID、作成日、作成者区分、本文］

整理項目：
1. 記録の目的
2. 日時
3. 関係者
4. 確認済み事実
5. 相手の発言
6. 要望
7. 課題
8. 影響
9. 制約
10. 期限
11. 担当者の観察
12. 担当者の解釈
13. 仮説
14. 未確認事項
15. 次に確認すべき質問
16. 次のアクション

ルール：
- 原資料にない内容を追加しない
- 不明な内容は推測しない
- 推測は必ず「仮説」と表示する
- 未確認事項は必ず「未確認」と表示する
- 数値、日付、固有名詞、単位を変更しない
- 相手の発言、担当者の観察、担当者の解釈を分ける
- 希望、検討中、決定済みを分ける
- 原資料間に矛盾がある場合は、勝手に採用せず両方を表示する
- 各行へ根拠となる原資料IDを付ける
- 安全、品質、原因確定、診断、服薬、緊急性、ケア方針、対外約束、最終承認は判断しない

出力形式：
表形式。各行は「項目｜整理結果｜根拠ID｜確定状態」の4列にしてください。

最後に別表として、
1. 原資料間の不一致
2. 追加確認が必要な事項
3. AIが判断できない事項
4. 自己点検で見つけた補完・断定の疑い
を表示してください。
```

## AI利用不可時

`outputs/raw_ai_output.md` を入力結果として扱い、`outputs/problem_analysis.md` の観点で問題を探す。修正指示を書いた後、`outputs/corrected_output.md` と比較する。
