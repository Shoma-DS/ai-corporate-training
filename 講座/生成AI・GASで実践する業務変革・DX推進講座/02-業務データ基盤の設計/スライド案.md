## 設計方針

- 2時間講座。フォーム入力から台帳設計・権限設計まで一連の業務フローとして扱う。
- GASの実装は第3回以降。今回は「GASが動きやすい台帳の形」を設計することに集中する。
- 画面操作はダミー環境のGoogleフォーム・回答先Sheets・管理台帳・Drive権限画面を使う。
- 公式ロゴは `素材/ロゴ/` の取得済み素材を使う。個人情報・社内情報は画面に映さない。
- 演習成果物: フォーム設計表・管理台帳列定義・権限・保存設計メモの3点。
- 録画動画形式のため「今から○分取ります」は使わず「動画を一時停止して〜分取り組んでください」を使う。
- 旧45枚構成のうち、密接に関連する2〜3枚組（設問設計の原則、画面共有デモ、列設計の細部、演習とまとめ）を1枚に統合し、情報量を落とさず30枚に再構成する。

### S04 今回の判断軸: フォーム・台帳・GASの役割を分ける
**ヘッドライン:** 「誰が入力・更新・処理するか」を列ごとに決めると、台帳が崩れない

**内容ブロック①：情報の入力元別分類**
| 入力元 | 内容 | 台帳上の扱い |
|---|---|---|
| フォーム（送信者） | 受付日時・依頼内容・連絡先など | 原本シートに自動追加 |
| 担当者（人） | ステータス・担当者名・対応メモ | 管理台帳で手動更新 |
| GAS（自動処理） | 受付番号・完了日時・通知ログ | GASが列に書き込む |
| AI（Gemini） | 分類ラベル・要約テキスト | 人が確認してから確定 |

**内容ブロック②：なぜ入力元を分けるのか**
- フォーム列を担当者が上書きすると、原本データが汚染される
- GASが書く列を人が上書きすると、自動処理が誤作動する
- Geminiの出力は人が確認してから台帳に反映する

**内容ブロック③：今日の設計での活用**
- フォーム設計表に「台帳の列名」を書く
- 台帳列定義に「入力元（フォーム/人/GAS/AI）」を記入する

### S08 Googleフォームは「入力の入口」: ばらばらな連絡を1つの形式に統一する
**ヘッドライン:** メール・電話・口頭でバラバラだった入力が、フォームで1行1件に揃う

**内容ブロック①：Before/After 対比**
| | Before（フォームなし） | After（フォームあり） |
|---|---|---|
| 入力経路 | メール・電話・Slack・口頭 | Google Formsに統一 |
| 入力形式 | 担当者によってバラバラ | 設問ごとに形式が固定 |
| 台帳への反映 | 担当者が手動転記 | 回答が自動で1行追加 |
| 記録の正確性 | 転記ミス・漏れが発生 | 送信者の入力がそのまま保存 |
| タイムスタンプ | 手入力または記録なし | 送信日時が自動記録 |

**内容ブロック②：フォームを使うメリット3点**
- 転記が不要になる(回答がそのままSheetsに保存される)
- 入力形式が揃う(選択肢・日付・数値を入力タイプで制限できる)
- タイムスタンプが自動付与される(受付日時の手入力が不要)

**内容ブロック③：フォームが向くケースの目安**
- 同じ情報を複数の人から繰り返し収集する
- 集めた情報をSheets・GASで処理したい
- 入力者のITリテラシーがバラバラでもルールを統一したい

- **図解パターン:** before-after-split

### S09 設問設計の原則: 1設問1情報・自由記述を減らす・必須と入力ルール
**ヘッドライン:** 設問の設計が甘いと、台帳のデータが揃わず自動化もAIも使えなくなる

**内容ブロック①：設問設計の4原則**
| 原則 | NG例 | OK例 |
|---|---|---|
| 1設問1情報 | 「氏名と所属を入力してください」（1つの設問に2情報） | 「氏名」「所属部署」を別設問に分ける |
| 必須項目を絞る | 全設問を必須にする | 集計・GAS処理に必要な設問のみ必須 |
| 説明文を入れる | 「カテゴリ」（何のカテゴリか不明） | 「お問い合わせの種類（製品・サービス・請求・その他から選択）」 |
| 迷わない選択肢 | 「大きい・普通・小さい」（曖昧） | 「高（翌日対応必須）・中（3営業日以内）・低（1週間以内）」 |

**内容ブロック②：自由記述と選択肢の比較**
| 比較軸 | 自由記述 | 選択肢（ラジオ・プルダウン） |
|---|---|---|
| 回答の表記 | バラバラ（「製品Aの件」「製品Aについて」） | 「製品A」で統一 |
| Sheetsでの集計 | COUNTIFで集計できない | COUNTIFで即集計可能 |
| GASでの分岐 | 文字列比較が複雑 | if/switch文がシンプル |
| Geminiでの分類 | 分類が必要 | 選択肢がそのまま分類ラベルに |

- 自由記述を残すべき場面: 詳細・背景・補足説明が必要な設問、Geminiで要約・分類する目的の設問

**内容ブロック③：必須設定の基準と入力ルールの伝え方**
| 設問の種類 | 必須にする | 任意でよい |
|---|---|---|
| GASで使う設問（カテゴリ・担当者割当） | 必須 | - |
| 集計・KPIに使う設問（種別・優先度） | 必須 | - |
| 連絡先（メール・電話） | 必須（返信が必要な場合） | 任意（返信不要な場合） |
| 詳細・備考・添付ファイル | - | 任意 |

- 入力ルールは設問の「説明文」欄で伝える(例: 「半角英数で入力」「例: 2026/05/01」)。プルダウン・ラジオで入力を制限し、テキスト入力をなくすのが最も確実。

### S10 入力形式の使い分けと注意が必要な設問タイプ
**ヘッドライン:** 設問タイプを目的に合わせて選ぶと、台帳のデータが揃い自動処理が動く

**内容ブロック①：設問タイプ対応表**
| 設問タイプ | 向いている用途 | GASやSheetsでの扱い |
|---|---|---|
| 短文（テキスト） | 氏名・会社名・件名など | 文字列として処理 |
| 段落（長文テキスト） | 問い合わせ内容・備考 | Geminiの要約・分類に使う |
| ラジオボタン（択一） | カテゴリ・優先度・種別 | IFやSWITCHで分岐しやすい |
| チェックボックス（複数選択） | 希望する対応方法など | カンマ区切りで保存される |
| プルダウン | 担当部署・商品名など | マスタと一致させやすい |
| 日付・時刻 | 希望日・締切日・希望時間帯 | DATE関数・期限比較に使いやすい |
| ファイルアップロード | 添付書類・画像 | Googleアカウント必須・管理者設定依存 |
| 評価スケール（1〜5） | 満足度・難易度 | 平均値・件数集計しやすい |

**内容ブロック②：チェックボックスとファイルアップロードの注意点**
- チェックボックス: 複数選択の回答はカンマ区切りで1セルに入る。GASで分割処理は可能だが設計が複雑になるため、可能ならラジオボタンに変更する
- ファイルアップロード: 回答者にGoogleアカウントが必要で、ファイルはフォームオーナーのDriveに保存され、管理者設定によっては使用できない。今日の必須演習には含まない

**内容ブロック③：設問タイプの選び方の目安**
- 集計したい → ラジオ・プルダウン・評価スケール
- GASで分岐させたい → ラジオ・プルダウン（選択肢を固定）
- Geminiで処理したい → 段落（長文テキスト）

**内容ブロック②：Sheetsの入力規則の設定方法**

### S24 条件付き書式と集計関数: 台帳を見える化し未対応を一瞬で把握する
**ヘッドライン:** 色分けと集計式を組み合わせると、目視確認の時間がゼロになる

**内容ブロック①：条件付き書式の設定例**
| 条件 | 色設定 | 数式または条件 |
|---|---|---|
| 期限超過 | 赤（背景） | `=AND(E2<>"完了", D2<TODAY())` |
| 期限3日前 | 黄（背景） | `=AND(E2<>"完了", D2<=TODAY()+3)` |
| ステータス「新規」 | 薄青（背景） | `=E2="新規"` |
| 担当者未割当 | グレー（背景） | `=F2=""` |

**内容ブロック②：よく使う集計関数の使い分け**
| 関数 | 用途 | 例 |
|---|---|---|
| COUNTIF / COUNTIFS | 条件に一致する件数を数える | `=COUNTIF(E:E,"新規")` |
| SUMIF | 条件に一致する数値を合計する | `=SUMIF(D:D,TODAY(),G:G)` |
| FILTER / QUERY | 条件を満たす行を抽出する | `=FILTER(A:G,E:E="新規")` |

**内容ブロック③：設定手順とダッシュボード設計の考え方**
- 条件付き書式: 「表示形式」→「条件付き書式」→「カスタム数式」で設定する
- ダッシュボードシートは「件数・未対応・期限超過・担当者別」の4指標で最初は十分。第5回でKPIダッシュボードを整える

- **図解パターン:** conditional-format-with-function-table
- **テンプレートID:** isometric-corporate-clean
- **スクリーンショット:** `スクリーンショット/sheets-conditional-formatting.png`（取得先: https://support.google.com/docs/answer/78413?hl=ja）

### S27 権限設計の基本とフォーム共同編集の注意点
**ヘッドライン:** 権限を設計してから共有すると、データの誤操作と情報漏洩を同時に防げる

**内容ブロック①：Google Drive・Sheetsの権限一覧と業務別設計例**
| 権限レベル | できること | 向いている相手 |
|---|---|---|
| 閲覧者 | ファイルを読むだけ | 報告を受け取るだけの管理者・他部署 |
| コメント可 | コメントを追加・返信 | フィードバックが欲しい場合 |
| 編集者 | ファイルを編集・追加 | 台帳を更新する担当者 |
| オーナー | 削除・権限変更・完全管理 | フォーム・台帳の管理担当者のみ |

| ファイル | 閲覧者 | 編集者 | オーナー |
|---|---|---|---|
| 原本シート | 管理者のみ | 権限付与しない | フォーム作成担当者 |
| 管理台帳 | 関係者全員 | 対応担当者 | 台帳管理担当者 |

**内容ブロック②：フォーム共同編集の注意点**
- フォームに共同編集者を追加すると、その人もフォームの設問を編集でき、回答先スプレッドシートにもアクセスできる場合がある
- 回答データを見せたくない人をフォームの共同編集者に追加してはいけない
- 回答先シートは、フォームとは別に権限を設定し、原本シートは「管理者のみ閲覧」に設定する

**内容ブロック③：「全員に公開」にしない理由**
- 個人情報・業務データが外部に流出するリスクがある
- 誰でも編集できると台帳の列名・ステータスが書き変えられる
- 出典: Google Docs Editors Help（フォームの共同編集者と回答先シートの扱い）

- **図解パターン:** permission-table-with-warning
- **テンプレートID:** isometric-corporate-clean
- **スクリーンショット:** `スクリーンショット/drive-share-settings.png`（取得先: https://support.google.com/drive/answer/2494822?hl=ja）
