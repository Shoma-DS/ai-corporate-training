### S05 DXは大きなシステム導入だけではない
**ヘッドライン:** 転記・集計・確認・通知の改善から始めると、投資ゼロでDXが動き出す

**内容ブロック①：Before/After 対比**
| | Before（手作業） | After（Google Workspace） |
|---|---|---|
| 問い合わせ受付 | メールをExcelに転記 | フォームで自動収集 |
| 集計・報告 | Excelを手動集計 | Sheetsで自動集計・グラフ化 |
| 確認・承認 | 担当者を呼んで確認 | ステータス列で全員が把握 |
| 通知 | 電話・口頭で連絡 | GASでメール自動送信 |

**内容ブロック②：DXの階層**
- レベル1: 手作業の電子化（紙→デジタル入力）
- レベル2: データの集約（バラバラな入力→フォームで統一）
- レベル3: 処理の自動化（集計・通知・分類をGASで自動化）
- レベル4: 意思決定支援（AIによる要約・分類・提案）
- 今回は**レベル1〜2の土台**を固める

**内容ブロック③：業種別の身近な例**
- サービス業: 予約確認メールの手打ち → フォーム+GAS自動返信
- 製造業: 日報をExcelで集約 → Formsで直接入力・Sheetsで集計
- 小売業: 棚卸し結果を紙で記録 → スマートフォンからForm入力
- 士業: 依頼受付をメールで管理 → フォーム台帳で進捗管理

### S07 今日の判断軸: 何を自動化し、何を人が確認するか
**ヘッドライン:** 自動化と人の確認を分けて設計すると、ミスなく業務が流れる

**内容ブロック①：自動化に任せてよい作業**
- 転記: フォーム回答を台帳へ自動追加（コピペをなくす）
- 集計: 関数・GASで件数・合計・遅延を自動計算
- 通知: 受付確認・完了連絡・リマインダーの自動送信
- 保存: ファイルの命名・フォルダ振り分け・バックアップ

**内容ブロック②：人が確認すべき4つの場面**
| 場面 | 理由 |
|---|---|
| 外部への送信（メール・請求・書類） | 誤送信・誤記載のリスク |
| 承認・決裁が必要な処理 | 権限・責任の所在を明確にする |
| AI（Gemini）の出力を使う場面 | ハルシネーション・情報漏洩の確認 |
| 例外・イレギュラーな依頼 | ルール外の処理は人が判断する |

**内容ブロック③：半自動という選択肢**
- いきなり全自動にしない。「下書きは自動・送信は人」「抽出は自動・判断は人」から始める
- この線引きは、S28（確認フローの設計）とワーク2のTo-Be記入で実際に使う

### S09 中小企業のDX現状: 取組差と「両輪」の考え方
**ヘッドライン:** DXの差はツールの有無ではなく、業務フロー整理とIT基盤を両輪で回せているかで開く

**内容ブロック①：IPA DX動向2025の要点**
- 日本の中小企業でDXを「推進中」とする割合は増加傾向（IPA DX動向2025より）
- 一方で「成果測定・KPI設定」まで行っている企業は少数
- 取組の差は「業務の電子化」から「自動化・AI活用」の段階で顕著になる

**内容ブロック②：小規模企業が直面する3つの壁**
| 壁 | 具体的な状況 |
|---|---|
| 人員不足 | 担当者が1〜2名で兼務、システム管理に手が回らない |
| コスト制約 | 専用システム導入が難しく、ExcelとメールのままDXが止まる |
| 知識不足 | 「何から始めるか」がわからず、ツール導入が目的化する |

**内容ブロック③：経営の仕組みとIT基盤の両輪**
- DXの進捗はITシステムの整備だけでは測れない（IPA DX推進指標 2025年版）
- 「経営の仕組み（KPI・組織・文化）」と「IT基盤」の両方が整って初めて成果が出る
- だから順序は、業務フローを整理してからツールを当てはめる。この講座の第1回が業務整理から始まる理由

**内容ブロック④：「小さく始める」が正解な理由**
- 大規模システムは導入後の定着が難しい。Google Workspaceは既存利用者が多く追加学習コストが低い
- まず「1業務・1フォーム・1台帳」から成功体験を作る
- 出典: IPA「DX動向2025」・「DX推進指標 自己診断結果 分析レポート（2025年版）」

- **図解パターン:** data-card-with-balance
- **テンプレートID:** isometric-corporate-clean
- **スクリーンショット:** なし（公式データは出典明記でテキスト化）

### S31 自動化に向く業務・慎重に扱う業務
**ヘッドライン:** 5条件を満たす業務から始め、例外の多い業務は台帳整備から入る

**内容ブロック①：自動化に向く5条件**
| 条件 | 内容 | 確認方法 |
|---|---|---|
| 頻度が高い | 毎日・毎週繰り返す | 棚卸しシートの「頻度」列 |
| 手順が明確 | 例外なく同じ手順で行える | ステップが固定されているか |
| データが揃っている | 必要な情報が一か所にある | 台帳・フォームの整備状況 |
| 復旧できる | 失敗しても手動で戻せる | ログ列・バックアップがあるか |
| 効果を測定できる | 時間削減・ミス削減を確認できる | KPIを事前に仮置きできるか |

**内容ブロック②：慎重に扱うべき3パターン**
| パターン | 内容 | 対応 |
|---|---|---|
| 例外が多い | 案件ごとに対応が異なる | まずAs-Isを言語化し、例外をルール化してから |
| 判断基準が曖昧 | 担当者の経験・感覚に依存 | 判断基準を台帳のステータス設計に落とし込む |
| 情報リスクが大きい | 個人情報・顧客情報・契約情報を扱う | 権限設計・ログ管理を先に整える |

**内容ブロック③：条件を満たさないときの進め方とやりがちな失敗**
- 手順が明確でない → まずAs-Isを書いて手順を言語化する / データが揃っていない → 第2回（台帳設計）から始める
- 失敗例: 台帳が整わないままGAS実装→列名ズレで停止 / 全自動で外部送信→誤送信で信頼を失う / 効果測定なし→「自動化したが使われない」

**内容ブロック④：業種別の判定例**
- サービス業: 予約確認メール → 毎日・手順固定・Forms連携可能 → 5条件クリア
- 製造業: 日報集計 → 毎日・手順固定・転記ミスあり → データ整備（第2回）から始める
- 士業: 申告期限リマインダー → 手順固定・頻度高い・効果測定可能 → 5条件クリア
