# 第3回 スライド構成案: GASによる業務プロセス自動化

対象講座: 生成AI・GASで実践する業務変革・DX推進講座
スライド枚数: 30枚 / 120分（2026-07-09改訂・旧40枚超構成から統合）
テンプレートID: isometric-corporate-clean（全スライド共通）
レイアウト標準: 1枚まるごとラスター画像＋固定レイアウトワイヤーフレーム参照（`skills/corporate-training-course-builder/references/assets/講座スライドレイアウトワイヤフレーム.png`）

---

## 設計方針

- GASを高度な開発技術ではなく、繰り返しの表作業を減らす「事務ロボット」として位置づける。
- 第2回で作ったフォーム・台帳設計を前提に、SpreadsheetAppで行取得・条件抽出・転記・集計・重複チェック・ステータス更新・ログ追記を扱う。
- コード丸暗記ではなく、入力元・条件・出力先・更新列・ログ出力を読み替える力を重視する。
- 旧40枚超構成の重複説明、章見出しの詳細表、デモ前後の反復、演習の再説明を統合し、情報量を落とさず30枚に圧縮する。
- 章見出し/現在位置スライドは第1回と同じく、現在章の番号・章名を特大で見せるヒーロー型にする。詳細な論点は次の通常スライドで扱う。
- 生成画像は `imagegen` / Codex App Server / GPT image 2 で1枚まるごとの完成ラスター画像として作る。SVG、HTML/CSS、canvas、PIL、後載せ文字は使わない。
- 録画動画形式のため「今から○分取ります」は使わず「動画を一時停止して〜分ほど取り組んでください」を使う。

### S08 コードは読む順番があると速い
**ヘッドライン:** 設定→取得→条件→出力→ログの順で読むと、知らないコードでも業務への置き換え点が見える

**内容ブロック1：読む順番**
1. 設定ブロック: シート名・列名・条件
2. 取得ブロック: `getSheetByName` と `getValues`
3. 条件ブロック: `if` / `filter`
4. 出力ブロック: `setValues` / `appendRow`
5. ログブロック: 件数・エラー・実行日時

**内容ブロック2：最小構文**
| 構文 | 実務上の意味 |
|---|---|
| `const` | 後から変えない設定値 |
| `let` | 処理中に変わる値 |
| `if` | 条件に合う行だけ処理 |
| `for` | 全行を1件ずつ確認 |

- **図解パターン:** process-flow

- 失敗しても元データを壊さない

### S14 読む・処理する・まとめて書く
**ヘッドライン:** GASは1セルずつ触るより、まとめて読んで配列で処理し、最後にまとめて書く方が安定する
